## 6. Regulated-data handling — `ca-personal-information`

**Active class:** California personal information. Petition scans are the sharp case —
names, addresses and signatures of third parties who are not our users and never
consented to us.

| Surface | Finding |
|---|---|
| `documents.embedding` | Derived from petition-scan OCR. Widened 384 → 768 by this release; **no new at-rest copy of user text** — the column exists precisely so `IVectorDBProvider`'s `content` copy is not made |
| New column `documents.embedding_model` | Model identifier only. Not personal data |
| Embedding provider traffic | Stays inside the node's trust boundary: the host Ollama daemon over `host.docker.internal`. **No petition text leaves the node for inference.** This is the architectural posture evidence for self-hosted inference |
| Logging | Reviewed in `/op-review`. Log lines carry counts and ids only; the batch-mismatch error reports lengths, never text. The duplicate-source warning logs `external_id`s, which are public identifiers |
| Fixtures | The regenerated `petition-retrieval-vectors.json` contains vectors over **synthetic** control text, not real scans |
| #1233 (filed by this work) | Records that recalibration requires photographing petitions, and that it must use a blank or self-signed sheet — never one carrying real signatures |

**No critical or high regulated-data exposure findings are open from this release's
review.** However `/op-data-scan` was **not run** — carried forward as E-7. Absence of
findings from a scan that did not run is not evidence of absence.

## 9. Deploy prerequisites

Tagging builds and publishes images. It does **not** complete this release.

1. `ollama pull nomic-embed-text-v2-moe` on the node (957 MB) — **before** the stack starts
2. Set `EMBEDDINGS_PROVIDER=ollama` in the node `.env` (requires opuspopuli-node#57, merged)
3. `./bin/op-deploy docker-compose-prod.yml docker-compose-prompt-service.yml`
4. Re-embed the 64 propositions — the migration NULLs their source hashes, so a sync or the backfill script regenerates them
5. Verify: four columns at `vector(768)`, `embedding_model` populated, first sync reports `failed=0`

**Rollback:** `down.sql` returns the schema to 384; re-embedding with the previous model
restores the corpus in ~300ms. Both directions rehearsed locally, neither against
production data (E-15).
