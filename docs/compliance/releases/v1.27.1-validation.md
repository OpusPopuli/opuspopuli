## 2. Why v1.27.0 shipped these — the part worth keeping

Both defects share one shape: **correct from every single file's point of view,
healthy on every check, and the feature did nothing.**

### 2.1 Vision OCR never ran

`OcrModule` carried the provider-selection rule in two places. Only the static
`@Module` factory learned the `vision` case; `forRoot` kept a hardcoded
Tesseract and never read `ocr.provider`. `forRootAsync` builds on `forRoot`, so
the one registration that supplies a prompt supplier was the only one that
could never select the provider needing it.

**What the verification actually proved.** Pre-release, the service was booted
with `OCR_PROVIDER=vision` and reported healthy, with
`OcrModule dependencies initialized` in the log. That demonstrated the module
*initialised*. It did not demonstrate which provider it *produced* — and the
boot assertion written to catch exactly this misconfiguration lived in the
factory that was not being used.

Detected in production by a contradiction no test asserted:

```
docker inspect → OCR_PROVIDER=vision
docker logs    → [TesseractOcrProvider] Initializing Tesseract OCR
```

**Control added:** tests assert the SELECTED provider (`getName()` matching
`^vision:`), not that the module started. Reintroducing the defect fails 3.

### 2.2 Attorney General summaries were fetched, then discarded

The v1.27.0 sync fetched 44 AG title-and-summary PDFs successfully and lost all
46 items to `Proposition.status: Invalid enum value ... received 'active'`.

The manifest requests a constant `pending` and the generated rule says so — but
it also carries `extractionMethod: "text"` with no selector, so the extractor
scrapes container text from a page titled "Active Measures". Extraction
succeeds, yields `active`, and `defaultValue` never applies.

**This predates v1.27.0.** Manifest v3, active since 2026-08-20, carried
`defaultValue: "active"` outright. That source had been rejecting 100% of its
items for three weeks.

**Why nobody noticed: a whole-batch rejection is a silent one.** Nothing
errored, the sync reported success, the warning went to a diagnostic field no
dashboard reads, and the row count simply did not move. Directly analogous to
#1220, where a correct code path declined every scan for two weeks.

**Control added:** status vocabulary reconciled deterministically in the mapper
rather than by instructing a language model. The hint had asked in capitals
since August and was ignored across multiple manifest generations.

### 2.3 A near-miss caught by the pre-push gate

The first implementation of 2.2 mapped `qualified` -> `passed`. The pre-push AI
review **blocked the push**, correctly: a measure that has qualified FOR THE
BALLOT has not passed, it is awaiting a vote, and the opposite claim would have
been rendered to citizens as fact.

`qualified` now maps to `pending`. `approved` and `rejected` are not mapped at
all — each means opposite ends of the lifecycle depending on the source. An
unmapped value still fails validation, because a wrong civic claim is worse
than a rejected batch.

Recorded because it is evidence the gate has caught a real defect, not only
that it exists.
