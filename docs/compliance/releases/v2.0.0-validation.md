## 2. Semver

**Major.** The GraphQL schema diff (`apps/frontend/__tests__/graphql/__fixtures__/schema.introspection.json`,
`v1.28.0` → `97d6cb6d`) removes or changes exactly two output fields:

| Field | Was | Now |
|---|---|---|
| `ExpenditureModel.date` | `DateTime!` | `DateTime` |
| `ExpenditureModel.payeeName` | `String!` | `String` |

A non-null output field that becomes nullable breaks a strict client. Every
other change is additive. The three new required arguments
(`cancelRegionSync(jobId)`, `requestBillSummary(billId)`,
`billSummaryStatus(billId)`) are on new fields. The v1.29.0 pack carried this
as exception EX-1 under a minor bump. Making the release major closes EX-1.

## 7. Regulated-data handling

`node --experimental-strip-types scripts/data-scan.ts --all` on `97d6cb6d`
(classes: `ca-personal-information`): **passed**, with 26 non-blocking
`medium` findings and 1 allowlist entry. **No critical or high finding is
open.**

All 26 findings are `email` reaching a log or error, in the auth flows. All
of them predate this release:

- `supabase.provider.ts`, `auth.service.ts`, `passkey.service.ts`,
  `users.service.ts`, `auth.resolver.ts` and `websocket-auth.service.ts` are
  unchanged since `v1.28.0`.
- `db-migrate.sh:148` (the admin bootstrap) dates from 2026-05-22.
- The `logger.spec.ts` findings are the PII-masking tests asserting the mask.

They are carried, not introduced (EX-13).

**Runtime trust boundary.** Inference is self-hosted: Ollama on the node,
models pinned by digest (#1284). No document text, prompt or user data
reaches a third-party model at runtime. This is distinct from the
development-time AI (Claude Code) that prepared this release, which is
qualified separately under `CTL-AIQ-001`.

**The deploy itself handles personal data.** The cutover replaces the civic
corpus with the UAT one while keeping production's user tables (runbook
§5a). The transfer exports civic tables only, so no dev account reaches
production and no production user data leaves the Studio. It refuses to
finish if any user reference that cascades on delete is left unmatched.
Verification requires every user, passkey and address count to match exactly.

## 8. Risk

| Risk | Status |
|---|---|
| A large release is hard to roll back | **Mitigated**: the `:previous` image tags, plus a verified backup taken in the window (runbook W3, N3). Migrations are additive apart from the two below |
| `finance_ie_cvr2_amendable` deletes CAL-ACCESS IE/CVR2 rows stored under the old key | **Accepted**: they're rewritten by the next finance sync, or arrive in the transferred corpus. Rolling back the images doesn't restore them; the W3 dump does |

| The host memory gate defers every model load without the probe | **Mitigated**: N4 installs the probe, and create-op-node 0.22.0 verify checks it |
| Prompt-service out of step with the backend | **Mitigated**: deploy order W4 before W5, and §5a.2 checks every `promptHash` resolves |
