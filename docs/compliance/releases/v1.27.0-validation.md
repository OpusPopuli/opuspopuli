## 6. Regulated-data handling — `ca-personal-information`

**#1248 changes which engine reads a petition photograph, not what is
retained.** The image is still dropped on the device (#1075); still only OCR
text is persisted; `documents.ocr_provider` records which engine produced each
transcription, so every row remains attributable.

Two properties deliberately preserved:

- **`blocks` returns empty rather than fabricated.** A VLM emits no per-word
  geometry. The signature-block scrub reads word boxes, and an invented one
  would put a stranger's name back in play while looking handled.
- **Inference stays inside our own trust boundary.** The vision model runs on
  the node. No scan content reaches a third party.

**Provenance posture:** `OCR_VISION_MODEL` is pinned separately from
`LLM_MODEL`, confining a Qwen-derived model to one declared job in one
auditable value while inference moves to a US-provenance model. `create-op-node`
carries a test that fails if the two constants are ever collapsed.

**#1249 improves attestation:** prompt text now exists only in prompt-service,
where it is versioned and content-hashed. An output produced from an inline,
unversioned copy could not be attributed afterwards; there are no inline copies
left.

## 9. Deploy — and what deploying does NOT do

**Order does not matter within this release** — no migration, no schema change,
no frontend tag. Standard `./bin/op-deploy` (it layers the prompt-service
overlay).

Two of the three headline changes need an action AFTER the deploy:

1. **Vision OCR needs its model.** `ollama pull qwen2.5vl:7b` (6.0 GB) on the
   node. Already present on us-ca. A node without it fails per scan, not at
   boot.
2. **The AG summaries need a re-sync.** Deploying ships the code and the
   manifest; it does not re-run the propositions source. Until that sync runs,
   production still holds all 52 title-echo summaries. The re-embed afterwards
   IS automatic — the staleness hash sees the changed text.

**The check that the release worked:** `25-0004A1` and `25-0005A1` stop sharing
`embedding_source_hash` `9f668ff8d88b`. If they still share it, the sync has
not run.

3. **prompt-service must be seeded.** After #1249 there is no inline fallback,
   so an unseeded service throws on first prompt fetch. `requirePromptServiceUrl`
   already refuses to boot without the URL in production; seeding is the
   remaining half.
