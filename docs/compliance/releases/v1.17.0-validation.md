## 6. Regulated-data handling

Active class: **`ca-personal-information`** (CCPA/CPRA). No PHI; `hipaa` not declared.

### A live exposure was closed in this release

`geocoding.service.ts` logged a resident's **street address**:

```
logger.warn(`Census Geocoder returned ${status} for ${addressLine1}, ${city}, ${state}`)
```

`warn` is emitted in production. This was **not** latent — street addresses were reaching
the log pipeline whenever the Census Geocoder returned a non-OK status, for an unknown
period. Both that line and its `debug` sibling now log city and state only, which still
separates a systemic geocoder outage from one bad address. A sweep found no other logger
call referencing `addressLine1`.

It was found only because #1094 required auditing `logger.debug` calls before making
`LOG_LEVEL` configurable — the feature made the latent half reachable, and looking for
that surfaced the live half. See E9 for the exposure-window gap.

### Other changes touching personal data

- **#1104** — CSRF cookie transport. No payload, no new storage. Reduces spurious logouts
- **#1098** — auth cookie headers; test-only, synthetic fixtures
- **#1115, #1116** — public records and public geometry. The `county_thresholds` FK
  deliberately borrows identity from `jurisdictions` rather than restating it

### Architectural posture (application runtime)

Inference runs self-hosted (Ollama) inside the platform's trust boundary; personal data is
not sent to a third-party model provider at runtime. Recorded here as the application's
data-handling posture. **Distinct** from how development-time AI tooling handles source
code, which is a separate qualification concern and is not evidenced by this pack.

**`/op-data-scan` was not run for this release.** See E5. Per-PR classification was
performed and is recorded in §1.

## 9. Post-deploy verification (required)

```sql
-- migration landed
SELECT to_regclass('county_thresholds'), to_regclass('county_adjacency');

-- constraints survived db push on boot (E8)
SELECT conname FROM pg_constraint
WHERE conrelid IN ('county_thresholds'::regclass,'county_adjacency'::regclass) AND contype='f';

-- boundaries finally loaded (231 / 0 before this release)
SELECT count(*), count(*) FILTER (WHERE boundary IS NOT NULL) FROM jurisdictions;
```

Then the region log's `BoundaryLoader:` line — it must report upsert counts rather than
`already loaded — skipping` — and an address resolving to its county, since county
representative resolution starts working as a consequence.
