## 6. Regulated-data handling — `ca-personal-information`

`hipaa` is not declared for this repo, so no PHI section applies.

Two changes touch CCPA/CPRA personal information:

- **#1203 ("Where you live")** derives the reader's jurisdiction stack from their stored address (`UserAddress`). The rebuild changes presentation, not storage or retention. No new field is exposed through GraphQL that was not already reader-scoped.
- **#1211 (audit `entityId`)** changes how the audit interceptor resolves entity identity for input-object mutations. Audit logging already applies PII masking with configurable retention (default 90 days).

**Architectural posture:** inference runs inside the operator's own trust boundary — self-hosted Ollama on the node, never a third-party API — so civic and personal data in prompts does not leave the deployment. This is the application's runtime posture and is recorded here as such. It is **not** to be conflated with how the SDLC's development-time AI handles source code, which is qualified separately under `CTL-AIQ-001`.

**`/op-data-scan` was not run for this release.** No critical or high exposure findings are therefore *confirmed closed* — the correct statement is that the scan is absent, not that it passed. Recorded as exception E-7.

**Known open PI issue, not addressed by this release:** petition scan photographs are retained in `audit_logs`. Tracked under the AI-architecture M0 work.
