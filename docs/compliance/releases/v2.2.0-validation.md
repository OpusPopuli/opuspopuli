## 2. Semver

**Minor.**
- **GraphQL (region subgraph), additive:** a `@Public` mutation
  `locateJurisdictions(input)` and a `@Public` query `jurisdictionsByIds(ids)`.
  The lookup is a mutation so the address can never travel in a GET URL.
  Nothing was removed or made stricter in the schema.
- **Behaviour made stricter, on purpose:**
  - The gateway now refuses more than 50 requests a second, 200 in 10 seconds
    or 600 a minute from one client, with a 429 and `Retry-After`. Before, it
    had no per-client GraphQL limit at all: Nest guards never run on Apollo
    Gateway operations.
  - Every per-IP key (auth limits, bill-summary cap, audit, logs) now uses
    `cf-connecting-ip`, or the **last** `X-Forwarded-For` hop from a trusted
    peer. Before, they used the first hop, which the client chooses.
  - The auth `@Throttle` limits now apply. Before, they were registered under
    `default`, a tier name the throttler doesn't have, and were ignored.
- **Prisma migration:** none. The point query now uses the existing
  `jurisdictions_boundary_gist_idx` through a `&&` prefilter.
- **Dependencies:** one override, `effect >=3.22.1 <4.0.0` (3.22.5), clearing
  GHSA-7589-6fvf-x4pw. No new dependency.

**Release order:** none. The current frontend uses none of the new fields.
The infra gate above is already met.

**What #1457 opens.** Two unauthenticated operations. The address lookup
calls the Census geocoder, so it carries its own budgets: 10 a minute and 60
an hour per client (/48 for IPv6), 2,000 an hour across all clients, and 30
point lookups a minute per client (/64). The id lookup takes at most 50
UUIDs. Inputs are validated: coordinates in range, a 2-letter state, a ZIP
or ZIP+4, bounded lengths.

**What #1457 closes.** A client could previously choose its own key for every
per-IP limit, had no GraphQL limit at all, and faced no working login limit.
Rate-limit state is bounded at 100,000 keys with expiry sweeps.

## 7. Regulated-data handling

`scripts/data-scan.ts --all` on `69984bf5`: **passed**, with 24 non-blocking
`medium` findings (`v2.1.0`: 25). **No critical or high finding is open.**

#1457 is the first change in a while that handles CCPA personal information
from visitors without an account: a street address or coordinates, with the
IP that sent them. Its data flow:

- **In:** a GraphQL mutation body, never a URL.
- **Processed:** geocoded through the Census geocoder (the same third party
  the signed-in address flow already uses), then a point-in-boundary query.
- **Out:** district ids and names. The device keeps the ids only.
- **Not stored, logged, audited or traced:** no table write; `@SkipAudit` on
  both operations (audit rows carry arguments and IP); geocoder logs carry
  the state only, no city; every outgoing span's query values redacted;
  rate-limit warnings carry a masked IP.

Two pre-existing exposures were found and fixed in the same PR: signed-in
address saves wrote the street address to Tempo (7-day retention, so traces
from before the deploy age out by itself a week later), and the login
lockout log printed an unmasked email and IP.

**Runtime trust boundary:** unchanged. Inference is self-hosted on the node.
The development-time AI is qualified separately (`CTL-AIQ-001`).

## 8. Risk

| Risk | Status |
|---|---|
| Visitors behind one NAT (an office, a library, a mobile carrier) share a budget | **Open, owner decision**: 50/s on GraphQL is far above a page's needs; the auth limits (5 logins, 3 registrations a minute per IP) may be tight. Raise them in `AUTH_THROTTLE` if so |
| The Worker's server-side reads would share one budget | **Not yet reachable**: today every gateway call comes from the browser. Needs an exemption before #1456 subtask 5 |
| A misconfigured trusted peer lets clients choose their key | **Mitigated**: loopback binding live (§1); only private and loopback peers are trusted, and on prod the peer is the tunnel container |
| Geocoder abuse through the open lookup | **Mitigated**: per-client and global budgets (§6) |
| Addresses in traces from before the deploy | **Ages out**: Tempo keeps 7 days |
| Rollback re-opens the limits gap | **Accepted**: rollback to `v2.1.0` restores the old (unlimited) behaviour; no data migration to undo |
