**#1085's outcome, which changes exception E4.** The observability shipped in this
release was used the same day to diagnose the four measures, and the diagnosis
contradicted the issue's own stated cause. It was the output token budget, not a
prompt problem: at 2000 tokens the two longest measures produced no parseable JSON;
at 6000 both analysed. Production went to **52 of 52 analysed, 0 recorded failures**.

The reason it had been undiagnosable was a one-line provider defect — Ollama's
`finishReason` was mapped from `done`, which is true whenever generation stops for
any reason, so a budget-exhausted response reported `stop`. The single field that
would have identified truncation pointed the other way.

The fix (#1096) is **not** in this release; it merged after the `v1.16.0` tag and
ships in the next one. E4 stands as written for v1.16.0 — this release makes the
failure visible and does not fix it — but the gap it describes is now closed on
`main`.

## 6. Regulated-data handling

Active class: **`ca-personal-information`** (CCPA/CPRA). No PHI; `hipaa` is not declared.

Two changes touch personal information:

**#1088 — Grafana user dashboard.** Reads `users`, `user_sessions`, `user_logins`,
`user_addresses`, `documents`. Controls in place:

- Aggregates only. No panel selects `email`, `first_name`, `last_name`, `ip_address`, or any `address_line_*`
- Geography stops at state; city-level aggregation was deliberately excluded
- The datasource is a read-only role with `SELECT` on five tables and
  `default_transaction_read_only = on`. Verified empirically: reads succeed, `DELETE`
  is refused, an ungranted table is refused
- Credentials supplied by environment; none committed

**#1095 — settings surfaces.** Consent records, login history, session metadata and
language preferences. No new data is collected; the changes correct how existing data
is read and displayed (enum casing at the GraphQL boundary, audit-action coverage for
login history, device naming for sessions).

**Architectural posture (app runtime).** Inference runs self-hosted (Ollama) inside the
platform's own trust boundary; personal data is not sent to a third-party model
provider at runtime. Recorded here as the application's data-handling posture. This is
**distinct** from how development-time AI tooling handles source code, which is a
separate qualification concern and is not evidenced by this pack.

**`/op-data-scan` was not run for this release.** See E5. No critical or high
regulated-data exposure findings are *known* to be open; that statement rests on
per-PR review rather than a scan.
