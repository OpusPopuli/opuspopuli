## 2. The issue's "expect ~2%" is right for propositions and wrong for minutes

That figure is #1212's measurement of the **offsets** contract, and the
proposition corpus is 528 offset-only claims — **zero** have ever carried a
quote, confirming the quoted template has never run here. ~2% is the honest
expectation for that family.

Minutes is different, and an exact string match badly understates it:

| Matching | Located |
|---|---|
| exact `position()` | **13 / 218** |
| whitespace-normalised, as `locateQuote` does | **94 / 218** |
| of the 124 still unlocated, containing an ellipsis (`locateElided` reassembles) | **118** |

So minutes is likely the bulk of what verifies. The issue warns that "a backfill
that reports high success is a backfill that skipped the gate" — true for
propositions, but a good minutes number would be **honest**, and it should not
be read as a bug. Saying so before the number exists rather than after.

The remaining unknown is `supportRatio` on each located quote. Only the run
answers that.

## 3. The judgement call: every proposition has a NULL cited-text hash

All 54 propositions with claims have `analysis_source_text_hash IS NULL` —
#1279's column post-dates every one of those analyses.

`#1279`'s convention is that NULL means "unknown", treated as stale. If the
backfill honoured that, all 528 claims would land `unverified/stale-source`
**without ever being scored**, and the acceptance criterion — that the
anchoring rate is reproducible as a query — could not be met for the family it
was measured on.

`resolveEvidenceSpan` already draws the right line: it reports `stale` only
when a stored hash is **present and differs**. A NULL falls through and is
scored against current text, which is exactly what #1212 did to produce the 2%.
So the backfill passes the recorded cited hash as-is; where it is NULL, no
staleness is claimed and no freshness is claimed either — the claim is scored,
and what it scores is recorded.

**What is stored** is the hash of the text the span resolved against, per the
column's own definition ("SHA-256 of the derived text `spanStart`/`spanEnd`
index into"). For any row where the span means anything the cited and current
hashes are the same value, because a mismatch is precisely what stops a row
reaching `verified`; they differ only on rows whose span has already been
disclaimed. Corrected in `claim-recorder.ts` as part of this issue.

## 3a. What the run actually produced

Run against the full dev corpus — 1,497 claims, 1 second:

| Family | verified | unverified | unsourced | total |
|---|---|---|---|---|
| propositions | **59** | 469 | 0 | 528 |
| minutes | **105** | 113 | 0 | 218 |
| representatives | 0 | 42 | **709** | 751 |
| **total** | **164** | **624** | **709** | **1,497** |

`snapped` is 0, and correctly so: minutes store no offsets, so a located quote
is a *derived* span rather than a corrected one (the #1293 gate fix). Nothing
in this corpus has both a quote and a span for the quote to disagree with.

Three results worth stating plainly, two of which contradict what was predicted:

**Propositions anchor at 11.2% (59/528), not ~2%.** The 2% figure is #1212's
measurement of `olmo-3:7b-instruct`; this corpus was generated by a different
model, and `MIN_SUPPORT = 0.3` is a permissive bar — 30% vocabulary overlap.
11.2% is this corpus's real number, and it is now reproducible as a query
rather than a figure in a report. Whether 0.3 is the right bar for a
citizen-facing "verified" label remains the open question it was in #1292.

**Minutes anchor at 48.2% (105/218)** — the family that quotes verbatim, as
expected, and the one carrying nearly two thirds of all verified evidence.

**709 unsourced is larger than the 579 `training` claims**, and the difference
is the finding: **130 of the 172 claims the model labelled `origin: 'source'`
— 76% — named no source field at all.** They are labelled as sourced and are
not. The gate files them `unsourced`, which is precisely the kind of claim
#1208 exists to make visible.

## 4. Design

Reuses #1293's normalisers and `recordClaims` **unchanged** — no second
mapping, which is why they were made shared rather than inlined.

| Family | `sourceText` | `sourceTextHash` | `claimSourceTextHash` |
|---|---|---|---|
| propositions | `fullText` | `fullTextHash` (generated) | `analysisSourceTextHash` |
| minutes | `rawText` | hashed at read time | — (no stored hash exists) |
| representatives | `null` | `null` | — |

- **Idempotent for free**: `recordClaims` replaces by `(subjectType, subjectId)`.
- **Concurrency-safe for free**: the advisory lock from the #1293 follow-ups
  serialises a backfill against a live generator on the same subject.
- **The distribution is read back as a query** over `evidence.state`, never
  accumulated in counters — the AC asks for the gate's measurement rather than
  "a summary the backfill wrote about itself", and those diverge the moment a
  write fails silently.
- Trigger follows the #1261 precedent: an admin-guarded `@Mutation` with an
  optional `limit`.
- Batched per subject to bound memory; `fullText` and `rawText` are large.

## 7. Risk register

| Risk | Severity × Likelihood | Mitigation |
|---|---|---|
| Backfill reports a flattering number by skipping the gate | **high** × possible | Distribution read back from stored rows, not accumulated; every claim goes through `verifyEvidence`, which is the only way `state` is ever set |
| `training` bio claims laundered into looking sourced | **high** × possible | #1293's normaliser already refuses to carry `sourceHint` into a citation column; 579 rows must land `unsourced`, asserted in a test |
| NULL cited hash silently treated as "fresh" | medium × certain without §3 | Documented as the judgement call of this issue, in the plan, the PR and the code |
| Re-running duplicates claims | medium × likely if wrong | `recordClaims` replaces; asserted by re-running inside a test |
| Holding large `fullText`/`rawText` in memory across 226 rows | medium × possible | Batched; one subject's text at a time |
| `locateQuote` re-normalises the source per claim (~4.5× per minutes row) | low × certain | Acceptable for a one-off; noted rather than left to be discovered under a larger corpus |
| Backfill races a live generator on one subject | low × possible | Advisory lock from the #1293 follow-ups already serialises this |
